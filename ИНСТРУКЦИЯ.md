## 4. Выложить страницы инфляции на сайт

### 4.1. Перед выкладкой
1. Запустить **Docker Desktop**: `open -a Docker` и подождать ~30 секунд (кит в строке меню перестанет анимироваться).
2. Проверить Яндекс Облако: `yc config list` должен показать `folder-id`. Если ошибка — `yc init` и войти.

### 4.2. Выкладка
```bash
cd "/Users/andrejkrylov/Desktop/Совкомбанк/Инфляция"
./deploy_inflation_site.sh
```
Что происходит по шагам (видно в выводе):
1. `Чистая копия сайта из последнего коммита` — во временную папку копируется сайт ровно таким,
   каким он записан в последнем коммите git.
2. `Кладу поверх две страницы инфляции` — копируются ваши текущие `inflation_weekly.html` и `inflation_monthly.html`.
3. `Проверяю JavaScript` — должно быть `OK` для обоих файлов. При `ОШИБКА` выкладка остановится.
4. `Собираю и выкладываю` — сборка Docker-образа и загрузка в облако, 3–6 минут.
5. Проверка: обе страницы должны ответить `200` (пароль скрипт берёт из `~/.config/macro/site_auth.env`).

### 4.3. Пароль сайта
Вкладка «Макропрогнозы» открыта всем, остальные вкладки — после входа: сайт сам покажет форму с логином и паролем
и запомнит вход на 30 дней (выйти — адрес `/logout`). Они хранятся на вашем компьютере
в файле вне папки сайта. Создать один раз:
```bash
mkdir -p ~/.config/macro && nano ~/.config/macro/site_auth.env
```
и вписать две строки (без пробелов вокруг `=`, без запятых):
```
BASIC_AUTH_USER=ваш_логин
BASIC_AUTH_PASS=ваш_пароль
```
Сохранить: `Ctrl + O`, Enter, `Ctrl + X`. Сменить пароль — поправить файл и выложить сайт заново.
Без этого файла `deploy_yc.sh` остановится и подскажет, что делать; `./deploy_yc.sh --no-auth` выложит без пароля.

### 4.4. Выложить сайт целиком
С 14.11.2026 все правки разделов закоммичены, поэтому сайт можно выкладывать прямо из папки сайта:
```bash
cd ~/Desktop/projectmacro/macro_forecast_site
git status --short        # что изменено и ещё не закоммичено
git add <файлы> && git commit -m "Описание изменений"
git push
./deploy_yc.sh
```
`deploy_yc.sh` выкладывает **всё, что лежит в папке**, включая незакоммиченное. Вернуться к состоянию сайта
до 14.11.2026 можно через ветку `before-2026-11-14`.

## 6. Частые проблемы

| Симптом | Что делать |
|---|---|
| В выводе выкладки `ERROR: … Container already exists: macro-forecast-site` | это нормально: скрипт каждый раз пытается создать контейнер, он уже есть — выкладка продолжается дальше |
| `docker не найден` / `Cannot connect to the Docker daemon` | `open -a Docker`, подождать, повторить |
| `yc не найден` / ошибки авторизации yc | `yc init`, выбрать облако и папку |
| `ОШИБКА  inflation_….html` при проверке JS | шаблон повреждён — не выкладывать и попросить ИИ починить. **Не делать** `git checkout -- templates/inflation_*.html`: в коммите старая версия страниц, это сотрёт все обновления инфляции. Живой сайт при этом не пострадает — выкладка остановится до сборки |
| Страница отвечает не `200` после выкладки | подождать 1–2 минуты и проверить снова; если не помогло — запустить выкладку ещё раз |
| Локально `python app.py` падает с ImportError | `source .venv/bin/activate`, затем `pip install -r requirements.txt` |

### 7.1. Вкладка «Рубль» — одной командой
После обновления котировок нефти (папка НГД), файла RMM или просто чтобы освежить фьючерсы и объёмы торгов:
```bash
bash data_scripts/update_ruble_tab.sh
```
Займёт 3–8 минут. Шаги:
1. Курс + прогноз (из RMM).
2. Декомпозиция курса и «Баланс потоков» (RMM + сводный файл ОРФР).
3. Нетто-позиции физлиц по фьючерсам (Мосбиржа, ALGOPACK).
4. Объём торгов юанем TOD+TOM (ALGOPACK).
5. Потребность экспортеров в продаже валюты.
6. Нефть и экспорт со сдвигом 1,5 мес.
7. Операции Банка России на валютном рынке + прогноз.
8. Проверка, что в данных нет `NaN` (из-за них график на сайте получается пустым).

В конце — сводка `ок` / `ОШИБКА` по каждому шагу. Если шаг упал из-за интернета (`timed out`, `URLError`) —
просто запустите команду ещё раз. Результат посмотрите локально (раздел 2: `$PY app.py`, адрес
http://127.0.0.1:5050/ruble — именно 5050).

С флагом `--deploy` (`bash data_scripts/update_ruble_tab.sh --deploy`) после успешных шагов сайт сразу выкладывается
через `deploy_yc.sh` — то же самое, что раздел 4.4 (выкладывается всё, что в папке). Делайте так, только когда
решили выкладывать.

### 7.2. «Рубль» по шагам (если нужно что-то одно)

**Курс + прогноз и таблица «Динамика USD/RUB по месяцам»** — после обновления RMM или в новый день:
```bash
$PY data_scripts/update_fx.py --model "/Users/andrejkrylov/Desktop/Совкомбанк/Рубль/Russia Mega Model.xlsx"
```
- факт — среднемесячный курс ЦБ (скачивается сам); текущий месяц — факт (среднее с 1-го числа), если прошло больше
  10 дней (порог — строка `MTD_MIN_DAYS = 10` в `data_scripts/update_fx.py`);
- прогноз — RMM, лист RUB, строка 273 «USDRUB fact + forecast»;
- таблица — изменение среднемесячного курса к среднемесячному за прошлый месяц.

**Декомпозиция курса, «Баланс потоков», пересмотр к снимку** — после обновления RMM или сводного ОРФР:
```bash
$PY data_scripts/update_ruble_data.py \
  --model "/Users/andrejkrylov/Desktop/Совкомбанк/Рубль/Russia Mega Model.xlsx" \
  --orfr "/Users/andrejkrylov/Desktop/Совкомбанк/Рубль/Операции на валютном рынке (ОРФР, сводно).xlsx"
```
Снимок прогноза (база графика «Пересмотр факторов модели к снимку», сейчас 28.10.2026) не меняется. Новый снимок —
только после обсуждения прогнозов: добавьте в конец команды `--new-snapshot`.

**Новый выпуск «Обзора рисков финансовых рынков» ЦБ (ОРФР)** — около 10-го числа:
1. На https://www.cbr.ru/analytics/finstab/orfr/ скачайте Excel к выпуску (файл вида `ORFR_2026-11.xlsx`).
2. Перенесите его в сводный файл (подставьте точное имя; копия старого — `… (ОРФР, сводно).bak.xlsx`):
   ```bash
   $PY data_scripts/update_orfr.py ~/Downloads/ORFR_2026-11.xlsx
   ```
   Скрипт напишет, какие листы обновил, а какие оставил прежними (например, «РВ продажи 29 экспортеров» —
   ЦБ не публикует их с ноября 2026 г.).
3. Запустите команду «Декомпозиция…» выше (или 7.1).

**Фьючерсы физлиц:** `$PY data_scripts/update_futoi.py` — печатает дату, нетто-позицию (млрд $) и изменение за 4 недели.

**Объём торгов юанем:** `$PY data_scripts/update_cny_volumes.py` — прошлые месяцы из кэша `data/cache/cny_volumes/`
(перекачать всё: `rm -rf data/cache/cny_volumes`).

**Потребность экспортеров и «Нефть и экспорт»** — подробно в инструкции папки «Модель экспортеров»:
```bash
cd "/Users/andrejkrylov/Desktop/Совкомбанк/Рубль/Модель экспортеров"
$PY need_model.py
$PY oil_exports.py
cd ~/Desktop/projectmacro/macro_forecast_site
```

**Операции Банка России на валютном рынке (+ прогноз):** `$PY data_scripts/update_cbr_fx_ops.py`. Ручные настройки:
- цена Urals на отдельные месяцы — `Совкомбанк/Рубль/Модель экспортеров/forecast.py`, строка `URALS_OVERRIDE = {...}`
  (на текущий месяц не действует: берётся фактическая средняя с начала месяца);
- цена отсечения — там же, `CUTOFF = {...}` ($59 в 2026 г., $50 с 2027 г.);
- операции ЦБ (регулярные/нерегулярные) — лист «Операции_ЦБ» в `Совкомбанк/НГД/НГД_входные_данные.xlsx`
  (ЦБ объявляет объёмы в конце июня и декабря — добавьте строку);
- оценка зеркалирования ФНБ на I пол. 2027 г. — строка `FNB_INVEST = [...]` в `data_scripts/update_cbr_fx_ops.py`.

**Важно (с 14.11.2026): данные на сайт попадают через хранилище, а не выкладкой.** Сайт читает файлы данных
из хранилища Яндекс Облака (бакет `macro-site-data`): JSON вкладок «Рубль», «НГД», «Модели ЦБ» и Excel-книги
«Макропрогнозов», «Прогнозов аналитиков», «Прогноза доходностей» и «ОФЗ». Выкладка (`deploy_yc.sh`, `release_all.sh`,
`--deploy`) их **больше не обновляет** — после обновления данных загрузите изменённые файлы в хранилище:
```bash
cd ~/Desktop/projectmacro/macro_forecast_site
# JSON (Рубль, НГД, Модели ЦБ) — подставьте нужный файл:
yc storage s3 cp data/ruble_fx.json s3://macro-site-data/data/ruble_fx.json
# Excel — макропрогнозы (7.3) и прогнозы аналитиков (7.4):
yc storage s3 cp macro_main_linked.xlsx s3://macro-site-data/excel/macro_main_linked.xlsx
yc storage s3 cp analyst_forecasts.xlsx s3://macro-site-data/excel/analyst_forecasts.xlsx
# Прогноз доходностей / ОФЗ:
yc storage s3 cp yield_forecast_data.xlsx s3://macro-site-data/excel/yield_forecast_data.xlsx
yc storage s3 cp "Денежный рынок – Ставки_исправлено_v2.xlsx" "s3://macro-site-data/excel/Денежный рынок – Ставки_исправлено_v2.xlsx"
yc storage s3 cp "Условия кредитования ЦБ.xlsx" "s3://macro-site-data/excel/Условия кредитования ЦБ.xlsx"
```
Docker для этого не нужен. Сайт подхватит файл в течение 1–2 минут — потом обновите страницу (`Cmd + Shift + R`).
Если файла в хранилище нет, сайт берёт копию, выложенную вместе с ним. Скоро это заменит одна команда публикации.

Кнопка выгрузки на главной (`/export`, открыта без пароля) отдаёт не всю книгу `macro_main_linked.xlsx`, а только
лист `main` — значениями, без ваших рабочих листов.

### 7.8. Частые проблемы с данными
| Симптом | Что делать |
|---|---|
| Пустой график на вкладке | в JSON попал `NaN` — 7.1 покажет файл на шаге 8; сообщите ИИ |
| `ALGOPACK …: 401` / `403` | истёк или неверный ключ → 7.0 |
| `PermissionError` / Excel не сохраняется | закройте файл в Excel и повторите |
| `ModuleNotFoundError` | запущен не тот Python — используйте `$PY` (7.0) |
| Ошибка интернета (`timed out`, `URLError`) | запустите ещё раз |
